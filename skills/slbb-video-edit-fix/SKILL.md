# AI 短剧 S6：剪辑修正

## 概览

这个技能用来把 S5 质检结论转换成人工剪辑修正方案和执行清单。

S6 是方案阶段，不是媒体剪辑阶段。它不剪视频、不渲染、不配音、不生成旁白、不替换音频、不导出成片。它给人工剪辑师清晰的修复指令，尤其是裁剪说明、简单遮罩说明、字幕/文字遮挡方案、音频问题说明，以及需要回到上游重生成的判断。

在 `long_drama` 模式下，S6 还要给出片段衔接判断：是否裁剪、加转场、重生成当前片段、请求补桥接镜头，或因为连续性无法靠剪辑修复而回到上游。

## 执行闸门

- 红色检查点：写剪辑方案前，先读取 S5 结论，只包含 S5 标为可安全剪辑，或明确接受进入 S6 的问题。
- 红色检查点：写 S6 前，必须说明本阶段只创建人工剪辑修正方案，不剪视频、不做配音。
- 红色检查点：进入 S7 前，需要用户确认方案，或用户提供已经修好的视频文件。
- 停止：如果问题是 `regenerate_required`，回到 S2/S3/S4，不要编造剪辑修复。
- 停止：如果用户要求 S6 直接剪视频、配音、合成旁白、渲染或导出最终媒体，拒绝该执行动作，只提供人工修正方案。

## 输入

优先使用工作流产物：

```text
artifacts/S4/generation_run_log.md
artifacts/S4/generation_run_log.csv
artifacts/S5/qc_report.md
artifacts/S5/qc_verdict.json
artifacts/S5/rework_suggestions.md
```

也可以接受：

- 视频文件路径或平台 URL
- 不需要的字幕/文字所在时间范围
- 剪辑师人工笔记
- 展示文字异常的截图/抽帧

## 工作流程

1. 创建 S6 骨架：
   ```bash
   python3 "skills/slbb-video-edit-fix/scripts/scaffold_s6_run.py" <run_dir>
   ```
2. 读取 S5 产物，识别哪些问题可以通过剪辑修。
3. 遇到字幕/文字异常，遵循 `references/subtitle_cover_standard.md`。
4. 添加每个手动修复项：
   ```bash
   python3 "skills/slbb-video-edit-fix/scripts/add_edit_fix_item.py" <run_dir> --fix-id fix-001 --type subtitle_cover --timestamp "0:00-0:15" --problem "即梦生成乱码字幕" --action "人工在剪映添加白底遮罩覆盖原字幕，黑体重打正确字幕" --acceptance "人工预览确认原乱码不可见，新字幕清晰可读"
   ```
5. 写入或更新：
   - `artifacts/S6/edit_fix_plan.md`
   - `artifacts/S6/edit_checklist.md`
   - 可选过程记录：`artifacts/_audit/S6_edit_log.md`
6. 验证：
   ```bash
   python3 "skills/slbb-video-edit-fix/scripts/validate_s6_outputs.py" <run_dir>
   ```
7. 停在人工闸门。用户确认人工剪辑方案，或提供修订后视频文件之前，不要继续进入 S7。

从包根目录运行上述命令；如果只拿到了单独 skill 目录，则改用该 skill 目录内的相对脚本路径。

## 规则

- 不要剪视频、生成配音、替换音频、渲染、导出，或声称媒体工作已经完成。
- 除非用户提供已剪辑文件，或确认已经在本技能外完成剪辑，否则不要声称视频已被剪好。
- 字幕遮挡默认使用白底黑字。
- 使用可商用粗体无衬线字体，优先黑体 / 思源黑体 / Noto Sans CJK 风格。
- 遮挡块必须完全盖住不需要的原字幕/文字。
- 保留故事含义。除非用户明确批准，不要改写台词。
- 如果问题无法靠剪辑修复，回到 S2/S3/S4，不要强行进入 S6。
- 如果 S5 说视频应该拒绝，不要创建可发布剪辑方案，只创建返工方案。
- S6 输出只是方案。如果用户提供外部已修版本，方案审查状态要标为 human-review-needed，直到用户确认。
- 不要用粗糙白块、假 UI 叠层或粘贴数字去修复剧情关键手机屏幕、银行余额、现金、票据、合同或其他核心爽点，除非用户明确接受这个视觉取舍。
- S6 可以描述人工如何降低坏音频、裁剪空白时间、加简单遮罩或请求替换音频。S6 不能自己生成、混音、配音或替换音频。
- 如果局部修复看起来比原问题更假，停止并回到 S2/S3/S4，或把缺陷标为接受/延后。

## 修复类型

- `subtitle_cover`：遮挡乱码/生成字幕或错误文字
- `caption_replace`：用正确文字替换可见字幕
- `trim`：指示人工剪辑师删除不可用的开头/结尾秒数
- `crop_or_mask`：指示人工剪辑师隐藏边缘瑕疵或不需要的文字
- `audio_note`：记录音乐、声音、旁白或配音修复说明，交给人工剪辑师
- `rework_only`：剪辑不可修，回到上游
- `accept_defer`：当前测试接受已知缺陷，不修复
- `bridge_shot`：在长剧片段之间增加或请求短桥接镜头
- `segment_regenerate`：当前片段在组装前应重生成
- `continuity_trim`：指示人工剪辑师裁剪或重排片段边缘，以保留节奏和情绪

## 长剧模式

当 `workflow_state.json.mode` 为 `long_drama` 时，S6 必须明确判断当前片段能否连接相邻片段：

- 使用 S5 长剧连续性质检结论作为输入。
- 把可剪辑修复项和必须重生成的问题分开。
- 如果身份、年龄阶段或故事逻辑坏了，回到 S2/S3/S4，不要用转场硬遮。
- 如果片段可用但衔接粗糙，创建 `bridge_shot`、`continuity_trim` 或人工音频转场说明。
- 除非用户提供已剪辑文件或确认已完成组装，否则不要声称 2 分钟影片已经组装完成。

## 必需输出

```text
artifacts/S6/edit_fix_plan.md
artifacts/S6/edit_checklist.md
```

见 `references/output_contract.md`。

S6 主输出应是干净的人工剪辑说明。能力边界、拒绝记录和人工闸门说明放到 `_audit`，不要放进剪辑方案本身。

## 失败模式

| 触发情况 | 必须动作 | 禁止的偷懒做法 |
| --- | --- | --- |
| S5 结论为 reject 或 regenerate_required | 创建仅返工方案，并回到上游。 | 产出可发布剪辑清单。 |
| 用户要求 S6 直接剪辑、配音、渲染或导出视频 | 拒绝媒体执行，只提供人工剪辑修正方案。 | 创建或修改视频/音频文件。 |
| 用户要求用叠层修坏掉的核心道具 | 说明视觉取舍，并要求明确接受。 | 粘贴假 UI/数字，假装恢复了原画面。 |
| 用户要求 S6 生成或替换旁白 | 给人工剪辑师写 `audio_note`，或回到上游重生成。 | 合成声音、混音或声称配音完成。 |
| 字幕遮挡漏出原文字 | 扩大遮挡区域，并重新检查时间戳。 | 接受部分可见的乱码文字。 |
| 剪辑会比原问题更糟 | 停止、回到上游，或标记接受/延后。 | 强行局部修补。 |
| 验证失败 | 先修方案/清单，再进入人工闸门。 | 带着无效 S6 输出继续进入 S7。 |

## 反模式黑名单

- 没有已剪辑文件或用户确认，不要声称视频已经剪好。
- 不要从 S6 直接裁剪、遮罩、配音、合成旁白、混音、渲染、导出或附加成片媒体。
- 不要把 S6 变成重生成、质检或平台发布。
- 替换字幕时，不要改写台词含义。
- 除非明确接受，不要用粗糙遮罩、假 UI 或粘贴数字修剧情关键道具。
- 不要把能力限制、草稿日志或人工闸门话术放进主剪辑说明。
- 不要把任何方案、脚本输出或未审查媒体叫作 `final`。

## 完成闸门

只有人工方案和清单都存在、验证通过，并且用户确认方案或提供外部已剪辑视频时，S6 才算完成。
